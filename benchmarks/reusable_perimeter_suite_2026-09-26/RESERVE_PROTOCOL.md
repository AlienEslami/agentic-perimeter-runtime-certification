# Reserve-plan refresh: separate availability extension

The widest sensing contracts can leave the archived continuation without a closing service enclosure, while other candidate plans under the same contract certify. Preserve this result and test a newly planned reserve before granting authority under that broader information contract.

For each original deadline contract whose archived continuation does not certify, optimize a fresh two-block network-TTS plan under the same initial information, arrival forecast and regional deadline. Independently certify it using the unchanged checker. If it fails, try a fixed moderate Region-2 weight of two. Stop at the first independently certified reserve. Both attempts and all failures are stored.

If the original nominal proposal is certified, its authority remains unchanged. Otherwise, apply the same ascending 0.05 command interpolation grid toward this new certified reserve. This is an explicit optional initialization/reserve-refresh tool, separate from retaining an existing suffix. It demonstrates availability case by case on the finite grid; it is not an unconditional existence theorem for arbitrary information sets or disturbances.

Development and held-out settings receive identical algorithms. The original comparison, including unavailable proofs, is preserved. Results of the extension are stored in `results/reserve_refresh/` and reported with their own denominator.
